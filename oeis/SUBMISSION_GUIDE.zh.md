## 一、要提交的是什么

**A185091** 定义：对第 n 个奇数 N = 2n−1，求最小的"非合数"q（即 q = 1 或素数），
使得 N = 2p + q 且 p 也是非合数。

**A002091** 是 A185091 出现"新纪录"的位置（N 值）；**A002092** 是对应的纪录值（q 值）。
直观地说：随着 N 增大，大多数 N 很容易分解，但偶尔出现"特别难分解"的 N，
需要用到前所未有大的 q——这些 N 和 q 就是这两个序列。

目前 OEIS 已发布 49 项，最后一项是 N = 8 567 125 268 699（q = 8821），
并注明"checked up to 10^13"（Pfoertner，2011）。

**我们的新发现**：下一个纪录出现在

- A002091 的 a(50) = **12 279 230 664 247**
- A002092 的 a(50) = **8969**

即在 8 567 125 268 699 之后，直到 12 279 230 664 247 才再次出现最小 q 超过 8821
的奇数，且该处最小 q = 8969（分解：N = 2 × 6 139 615 327 639 + 8969，两数均为素数）。

## 二、算法为什么是对的（你需要能向编辑解释）

程序 `src/verify2.cpp` 做的事分两层：

1. **分段筛**：要判定 (N−q)/2 是否为素数，需要知道 N/2 附近数的素性。程序用
   埃拉托斯特尼筛的分段版本：先筛出所有 ≤ √NMAX 的"基础素数"，然后把大区间切成
   2^28 宽的段，对每段用基础素数标记合数。原理与手工筛质数完全相同，只是分段
   以控制内存。**正确性依据**：任何 ≤ X 的合数必有 ≤ √X 的素因子，所以用全部
   ≤ √X 的素数去标记就不会漏。
2. **逐个求最小 q**：对每个奇数 N，按 q = 1, 3, 5, 7, ...（非合数）依次检查
   (N−q)/2 是否素数，第一个成功的 q 就是 A185091 的值；跟踪其运行最大值即得纪录。

**三重正确性证据**（编辑若质疑，按此回答）：
- 两个独立实现（verify.cpp 单体位图版 / verify2.cpp 分段多线程版）在 10^10 内
  输出完全一致；
- 程序输出与 OEIS 已发布的全部 49 项**逐项吻合**（这是对程序最强的第三方校验）；
- 新项的"点断言"可用 30 行纯 Python 独立复核（见下）。
